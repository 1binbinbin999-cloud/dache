# P1 开发经验（2026-11-19）

## 成功的方案及原因
1. **P1 从 P0 复制一份新目录，而不是在 P0 上直接改**：jarvis-p1 是 jarvis-p0 的复制 + 记忆模块，P0 保留为回滚点。成功原因：每轮一个可回滚版本，出问题能立刻回到上一轮，不用在 git 里翻。
2. **先用规则模板提取，不调 LLM**：100 条合成对话全部用“我喜欢 X / 我的目标是学会 X”模板提取，0 隔离。成功原因：先证明治理流程本身成立，再谈提取质量；如果一开始就用 LLM 提取，流程 bug 和模型错误会混在一起，分不清。
3. **写时 gate 用确定性子串规则**：注入 9/10 拦截，可解释、可复现。成功原因：安全边界必须在代码层，不靠模型自觉；规则简单反而容易测试。
4. **修正不删除旧版**：旧事实标 superseded + Correction 记录，新事实另起一条。成功原因：记忆的正确性靠历史可查，不是靠把错的删干净；测试 4 直接验证了这一点。
5. **注入测试里故意留一条正常事实**：第 9 条“用户喜欢吃辣”是正常事实，gate 接受是预期的。成功原因：只测拦截率会逼 gate 变得过度敏感，留一条正常样本能证明 gate 不是见什么都拦。

## 失败的方案及原因
1. **extract_facts 键名与 add_fact 签名不一致**：首次手动跑就报错 TypeError。失败原因：字典解包传参时没逐字核对签名。修复后已通过，教训记在问题记录里：新增内部接口先写最小调用测试再接 CLI。
