# P0 开发经验（2026-11-19）

## 成功的方案及原因
1. **只用标准库**：P0 只用 sqlite3、json、argparse、pathlib，无第三方依赖。成功原因：云端无 Docker、无 Ollama、无 pip 安装保障，标准库是唯一“复制即跑”的选择；也直接证明了 Core 不依赖模型生态。
2. **种子任务固定 id + INSERT OR IGNORE**：重复启动不重复写，幂等测试一次通过。成功原因：把幂等做进 SQL，而不是靠应用层先查后写。
3. **启动顺序写死在代码里**：config → database → policy → audit → scheduler，每步 append 到 boot_steps，测试直接断言顺序。成功原因：顺序是架构红线，写死比配置灵活更重要。
4. **事件日志 JSONL 追加写**：重启不丢、只追加，测试用“新日志以旧日志开头”验证。成功原因：追加写是最简单的不可变日志，不需要数据库事务。
5. **先写测试再跑**：tests/test_p0.py 用 subprocess 跑真实 CLI，不 mock 核心路径。成功原因：测的是用户真正会跑的命令，不是内部函数。

## 失败的方案及原因
- 本轮无失败方案。唯一走弯路的念头是“一开始就引入 PyYAML / LangGraph”，被否决：P0 的目标是证明“Core 不依赖模型”，引入重框架会反过来掩盖这一点。记下来：框架留给 P2 之后，先证明裸核能跑。
