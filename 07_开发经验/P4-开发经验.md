# P4 开发经验（2026-11-19）

## 成功的方案及原因
1. **建任务时校验，不等到运行时**：create() 里每步工具不在注册表就拒绝建任务。成功原因：错误越早发现越便宜；测试 3 证明未知工具在建任务时就被拦住，不会等到跑了一半才炸。
2. **失败分支先写，再写成功分支**：run() 里先写 denied/failed 的停表逻辑，再写 done 的 hash 记录。成功原因：规划器的核心价值是“失败时不乱走”，不是“成功时跑得快”；先把停表逻辑钉死，成功路径自然跟着走。
3. **重跑一致性用 result_hash 断言**：测试 4 比较两次跑的每步 hash。成功原因：重跑一致不能靠“状态都是 done”证明，要靠结果本身相同；hash 是最便宜的相等性证明。
4. **固定 id 幂等解决重跑重复写**：memory-add 带固定 id 时，add_fact 已存在即返回 already_exists。成功原因：重跑的本质是“同一操作再做一次”，写操作必须幂等，否则重跑一次就多一条记忆；这个幂等是 P4 补在 memory.py 里的，不是 planner 里特判的。
5. **P3 待定项在 P4 开头就定，不拖**：审计脱敏摘要和 actor 区分在写 planner 之前就定案并写进 gateway.py。成功原因：待定项越拖越难补，P4 一开始就把它们当作前置条件，测试 6 直接验证。
