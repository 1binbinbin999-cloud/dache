# Jarvis 技术决策记录（ADR）

> 状态说明：已确认 = 用户确认；建议待验证 = Muse 建议，须原型验证后由用户确认；待决策 = 等用户决定。
> 每条决策必须写：背景、决定、理由、替代方案、后果、验证方式。

## ADR-001：编排骨架用 LangGraph（建议待验证）
- 背景：需要有状态、可中断、可恢复、可审计的 Agent 编排。
- 建议：LangGraph 核心库 MIT，图状态 + 检查点天然对应闭环。
- 替代：Microsoft Agent Framework（.NET/Azure 偏重）、CrewAI（角色分工直观但图不如 LangGraph 灵活）、OpenAI Agents SDK（默认走 OpenAI，不作 Core）。
- 验证：P0 用 LangGraph 或纯 Python 状态机做最小闭环，对比可维护性后再定；P0 先不用重框架也可以，关键是 Core 不依赖模型 SDK。
- 状态：建议待验证。

## ADR-002：模型路由用 LiteLLM 自托管 Proxy（建议待验证）
- 建议：统一 OpenAI 兼容接口，100+ 供应商，负载均衡、故障切换、预算、成本追踪；自托管，不暴露公网。
- 注意：2026-03 曾有 PyPI 植入事件报道，部署时必须固定版本、校验签名、放内网、密钥隔离。
- 替代：OpenRouter（托管，只能作可选上游，不能作唯一路由）、Portkey（收购后路线待复查）。
- 状态：建议待验证。P0 先用配置映射 + Stub，不实际接入付费 API。

## ADR-003：本地推理用 Ollama + llama.cpp（建议待验证）
- 建议：Ollama 为默认本地入口，llama.cpp 为底层引擎；vLLM 留给后期 GPU 服务器。
- 注意：Ollama 新版有云模型标签，部署配置必须显式关闭云模型（OLLAMA_NO_CLOUD=1 或等效配置）。
- 状态：建议待验证。P0 先不装 Ollama，只留接口；P1 记忆测试时再决定是否安装。

## ADR-004：事实库用 Postgres + pgvector，P0 用 SQLite 同构 schema（建议待验证）
- 建议：最终用 Postgres + pgvector 做唯一事实库（事实+向量+审计），备份就是 pg_dump，迁移就是拷文件 + 导出 SQL。
- P0 折中：云端无 Docker/Postgres，P0 用 SQLite + 文件（Markdown+JSON），schema 与 Postgres 同构，字段 id/type/claim/confidence/evidence_grade/source/created_at/superseded_by 齐全，P2 再验证 Postgres 迁移。
- 替代：Qdrant（备选向量服务）、Chroma（原型快，生产不建议当唯一库）、Milvus（个人系统过度设计）。
- 状态：建议待验证。

## ADR-005：记忆提取只用 Mem0 开源库做适配器，真理在 Jarvis 自己的 schema 里（建议待验证）
- 理由：Mem0 图记忆已移出开源 SDK，新算法改为 add-only，只增不改，过期事实不会自动取代；直接当真理库会污染。
- 做法：Mem0 只做提取，写入必须经 Jarvis 的写时 gate、证据等级、supersede、不删除旧版、人工复核。
- 状态：建议待验证。

## ADR-006：知识检索用 Hybrid RAG，不上 Microsoft GraphRAG（建议待验证）
- 建议：BM25/全文 + 向量并行取 top-50，再本地 reranker 精排 top-5；Docling 本地解析，BGE-m3 本地 embedding。
- 不上 GraphRAG 第一版：索引贵、增量难，个人知识库用不上全局社区摘要；LightRAG/Graphiti 留第二阶段按需评估。
- 状态：建议待验证。

## ADR-007：工具协议用 MCP，但权限不在 MCP 里做（建议待验证）
- MCP（Anthropic 2024-11 发布）只解决“怎么暴露工具”，不解决“允不允许调用”；规范要求 Host 调用前获用户明确同意，授权本身可选，NSA 指出 MCP 目前不支持实例化时交换 RBAC。
- 做法：权限在 Jarvis 自己的 Gateway 代码里做：能力卡、allowlist、参数校验、审批分级 L0/L1/L2/L3、沙箱、审计。
- 状态：建议待验证。

## ADR-008：语言与运行形态（待决策）
- 候选：Python（Agent 生态最成熟，LangGraph/LiteLLM/Mem0 均为 Python 优先）。
- 替代：TypeScript（若用户偏好或后期要做 Web 界面）。
- 状态：待决策。P0 计划默认 Python 3.12（云端已装 3.12.3），如用户要求改语言，P0 前改成本最低。

## ADR-009：自我改进不可变规则代码化（建议待验证）
- 规则：永不改评估器、永不改 CI 配置、永不改测试文件以通过测试、永不提交密钥；提案隔离、金丝雀、冻结评估集、Git 回滚。
- 状态：建议待验证，P3 自我改进原型时验证。

## ADR-010：第二阶段总预算调整为 0 美元（2026-11-19，用户决定）

- **决定**：第二阶段总预算由 30 美元调整为 **0 美元**；单项测试上限由 5 美元调整为 0 美元。
- **规则**：所有开发、测试、API 调用、部署和运行费用必须为零；禁止开通付费服务、购买额度或产生自动扣费；首批两家模型供应商必须能在零成本条件下完成实际接入测试；免费额度必须确认有效性、使用限制和是否需要绑定付费方式；不得将需要付费才能继续使用的服务视为免费方案；优先使用本地模型、开源工具和免费服务；某项测试无法在零预算下完成时，记录原因、替代方案和未验证事项，不得自行突破预算；不得为了节省费用而擅自改变 Jarvis 的核心架构和长期目标。
- **依据**：用户 2026-11-19 20:43 的预算调整指令；零预算是硬性约束，不是临时优惠。
- **影响**：第一阶段实际花费 $0 不变；第二阶段候选方案见 `00_项目总纲/第二阶段候选方案.md`，推荐 Ollama 本地 + Gemini API 免费层，DeepSeek 官方 API 因无免费层被否决；免费层信息须在接入前于官方页面复核（Step 0）。
- **状态**：已决定，待用户批准第二阶段方案后执行。
