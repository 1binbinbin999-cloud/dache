## 2. 各模块职责

| 模块 | 文件 | 职责 | 状态（第一阶段末） |
|---|---|---|---|
| Agent Core | `core.py`、`jarvis.py` | 确定性编排：固定启动顺序、事件日志、任务库、健康检查；不 import 模型 SDK | 已实现（P0–P5） |
| Memory | `memory.py` | 长期记忆：提取、分类、去重、检索、更新、纠错；写时 gate、隔离区、Correction 记录、过期标记、JSONL 导出/导入 | 已实现（P1–P2） |
| Model Router | `router.py` | 逻辑模型名映射（config）、Stub 供应商、切换链、L0 规则降级、调用审计 | 已实现（P2，Stub） |
| Tool Gateway | `gateway.py` | 唯一工具入口：注册表（副作用等级）、权限检查在执行前、拒绝只记审计 | 已实现（P3） |
| Planner | `planner.py` | 任务分解为有序步骤、经网关顺序执行、状态追踪、可重跑 | 已实现（P4，模板+用户给定步骤） |
| Improvement | `improvement.py` | 自我改进六步流程、不可变规则、部署备份与回滚 | 已实现（P5） |
| Permission/Policy | `config.yaml` policy 节 + `gateway.py` check() | 策略表：允许/拒绝工具、destructive 一律拒绝、external 需开网络 | 已实现（P3，代码表） |
| Audit | `data/events.jsonl` | 追加写操作日志，与业务数据分离；参数只记 hash 与键名摘要 | 已实现（P0–P5） |
| Sandbox | `sandbox.py` | 真断网演练：unshare 命名空间内跑 boot + router-call | 已实现（P3） |

| User Model | — | 动态用户模型：思考/判断/决策习惯、目标、变化史，可被新证据修正 | 未实现（记忆表 memory_facts 暂代部分功能） |

## 3. 数据流（一次任务，以 P4 的 morning-brief 为例）

1. Situation：用户下达目标“早上简报”→ plan-create 建任务（步骤已给定或用模板）。
2. Context：Core 从 Memory 只读召回当前事实（memory-recall，经网关）。
3. Options：Planner 的步骤即选项序列（本阶段无模型生成选项）。
4. Decision：按步骤顺序执行；高风险步骤由网关拒绝即停。
5. Action：Gateway 按 allowlist 执行，router-call 走 Router（现为 Stub）。
6. Outcome/Result：工具返回记入 Audit（tool_call / router_call，含结果 hash）。
7. Learning：改进需求写成提案，走 P5 六步流程，不直接改代码。

## 4. 调用关系（允许 / 禁止）

允许：
```
用户/事件 → Agent Core → Planner →（步骤）→ Tool Gateway → 工具/Router
Router → Stub /（第二阶段）LiteLLM Proxy → 供应商
工具返回 → Gateway（标记为观察）→ Core → Audit；记忆写入经 Memory 写时 gate
```

禁止（架构红线）：
- 模型 / Router 不得直接调工具、直接写 Memory、直接改 Policy/Audit/代码。
- Planner 不得直接调工具，只能产出步骤给 Core 经网关执行。
- 工具不得直接读 Core 状态、直接写数据库、直接调其他工具。
- Memory 不得被工具输出直接写入；必须经来源标注、隔离、Core 校验。
- Improvement 不得直接改代码、配置、权限；只能产出提案走六步流程。
- local 逻辑模型失败时不得回落云端（P2 已修正，JIS-009）。

## 5. 模型供应商可替换（核心保证）

- Jarvis 代码只用逻辑模型名（fast / capable / reasoning / local / embedding），映射表在 `config.yaml` 的 model 节，不进业务代码。换模型只改配置（P2 测试 1 已验证）。
- Agent Core 不 import 任何模型供应商 SDK（P0 测试：grep 与 sys.modules 检查均无命中）；启动路径不调用 LLM。
- 第二阶段接入真实供应商时走 LiteLLM 自托管 Proxy 占位（config 中 `litellm_proxy_enabled: false`，启用时才打开），供应商之间切换仍只改配置。
- 降级分层 L0–L3：L3 云端增强可丢；L2 规则/检索本地；L1 本地模型（Ollama）；L0 硬核（Python 核心、SQLite、配置、策略、审计、调度器、网关）绝不依赖模型。外部 AI 全停时，启动、读记忆、读知识、本地工具完全保留（设计目标；真实全停演练尚未做，留第二阶段）。

## 6. 总体原则（保持不变）
- Local First、Cloud Optional；核心、记忆、知识、用户模型、权限独立；外部模型可替换。
- 可迁移：复制整个 `Jarvis/` 目录即可导出；每轮版本目录完整可运行；记忆库可导出 JSONL 并导入新环境（P2 测试 7）。
- 可扩展：新工具进注册表 + policy，不改网关代码；新模型进 config 映射，不改业务代码；新改进走 P5 六步流程。
