### 1. 测试 2 不是真断网验证（未解决，留后续）
- 现象：测试 2 只清空了 API Key 环境变量，证明启动不依赖 Key；“无网”靠代码不发起网络调用 + config 禁止来保证，未做系统级断网验证。
- 原因：云端环境无权限做网络命名空间隔离，且 P0 代码本身无网络调用，断网验证的边际收益低。
- 后续：P3 工具网关做沙箱时，一并做系统级出站拦截验证；或在实体机部署演练时做真断网启动测试。
- 状态：未解决，不阻塞 P0 验收。

### 2. config.yaml 未用真正的 YAML 解析器（设计取舍，已接受）
- 现象：P0 只做最小文本检查（`model_enabled: false` 是否在文件里），不用 PyYAML。
- 原因：避免 P0 引入第三方依赖，保持“只用标准库、复制即跑”。
- 后续：P1 需要读更多配置字段时，引入 PyYAML 或改用 JSON/TOML（标准库 tomllib 可读 TOML），在 P1 计划里决定。
- 状态：已接受的取舍，记入经验。

### 3. health() 会顺带初始化数据库（设计取舍，已接受）
- 现象：health 检查里调用 store.init()，会建表并写入种子。
- 原因：健康检查需要验证“数据库可读”，建表是幂等的，无副作用。
- 后续：如需严格只读的健康检查，P1 再拆分 init 与 read。
- 状态：已接受。
