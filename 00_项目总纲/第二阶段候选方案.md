# Jarvis 第二阶段候选方案（修订版，2026-11-19）

> 修订说明：本版按用户 2026-11-19 20:57 修订指令改写。术语统一为“模型接入后端”；$0 预算的解释收紧；免费条件一律标记未核实；LiteLLM 改为待比较的选项；实体机部署改为先盘点再定方案。
> 前提：第二阶段总预算 **$0**（用户决定，2026-11-19 20:43，见 ADR-010）。原 $30 上限与单项 ≤$5 不再适用，单项测试上限改为 $0。
> 本文件是候选方案与分析，不是开发计划。开始第二阶段开发前，仍需用户批准方案与首批模型接入后端。

## 0. 术语与 $0 预算的定义（修订新增）

### 0.1 术语
- **模型接入后端**：Jarvis 通过 Router 调用的模型来源，统称。分两类：
  - **本地推理后端**：模型跑在用户自己的电脑上，如 Ollama + 本地权重。无 API 账单，无外部依赖。
  - **云端 API 供应商**：模型跑在别人的服务器上，通过 API 调用，如 Gemini、Groq、OpenRouter、DeepSeek。可能产生账单，必须逐项核实。
- 本文件不再单独用“供应商”指代全部后端；凡指云端才用“云端 API 供应商”。

### 0.2 $0 预算的含义
- $0 不是“最终账单为零就行”，而是**整个开发过程不得产生未经批准的付费义务或扣费风险**。
- 以下行为默认不允许，每一项都需要用户逐项明确批准，缺一不可：
  - 绑定银行卡或任何支付方式；
  - 开通计费账户（含“先绑卡、后免费”的任何形式）；
  - 自动升级套餐；
  - 超额计费（含“超限自动按量付费”的任何条款）。
- 免费额度必须在官方页面核查，核查内容：是否免费、额度与限制、是否需要绑定付费方式、超限后是停用还是计费、数据使用条款。**未核实前，任何云端 API 供应商不得标记为可用。**
- 某项测试无法在零预算下完成时，记录原因、替代方案与未验证事项，不得自行突破预算，不得把付费服务写成免费方案。

### 0.3 免费条件核查状态（修订新增）
| 云端 API 供应商 | 免费条件 | 状态 |
|---|---|---|
| Gemini API | 免费层额度、限制、是否需绑卡——以官方定价页为准 | **未核实，不可用** |
| Groq | 免费计划额度、限制、是否需绑卡——以官方速率限制页为准 | **未核实，不可用** |
| OpenRouter | `:free` 模型额度、限制、是否需绑卡——以官方文档与模型页为准 | **未核实，不可用** |
| DeepSeek 官方 API | 见方案 D，已否决 | 不适用 |

> 以下各方案中出现的免费额度数字（如 Groq 的 30 RPM、OpenRouter 的 50 RPD）均来自 2026-11-19 的公开搜索结果（多为第三方转述），**未核实，不得作为决策依据**，仅作为 Step 0 核查时要去官方页面逐项确认的线索清单。

## 1. 第二阶段目标
1. 真实模型接入后端：把 Router 的 Stub 换成至少两个真实模型接入后端，验证切换、费用（$0）、超时与降级。
2. 真实失败演练：拔 Key、断代理，验证真实网络超时时的切换行为（闭环 JIS-011）。
3. 实体电脑部署演练：先盘点硬件与系统环境，再定本地模型与部署方案，然后做导出、安装、数据恢复、真机离线启动（闭环 JIS-015 部分）。
4. 遗留问题处理：JIS-007、010、013、016、017、018、021、022、023 按台账推进。

## 2. 候选方案对比

### 方案 A（推荐）：本地推理后端 Ollama + 云端 API 供应商 Gemini 免费层
- **技术路线**：local 逻辑模型 → Ollama 本地小模型；fast/capable → Gemini API 免费层模型（Flash 系列）；Router 映射只改 config；接入方式见第 3 节（直接适配器 vs LiteLLM，待用户决定）。
- **费用**：本地部分 $0 确定；云端部分**未核实**——Gemini 免费层是否免费、是否需绑卡、超限后是否计费，一律以 Step 0 官方核查结果为准。核查失败即换备选组合。
- **数据注意**：免费层内容可能被用于改进产品与人工审核——**只用合成测试数据，绝不用真实用户数据**。
- **风险**：免费层速率限制、模型名单、政策可能调整；云端 1.5 核共享 CPU 跑本地模型会很慢，小模型 smoke test 可能需要较长时间。
- **验证步骤**：Step 0 官方核查 → Step 1 最小调用（10 次以内，记 token 与费用）→ Step 2 切换/降级演练 → Step 3 速率与质量基线。

### 方案 B：Groq 免费计划 + OpenRouter :free
- **技术路线**：fast/capable → Groq 免费计划的开源权重模型；reasoning/embedding → OpenRouter `:free` 模型；Router 映射只改 config。
- **费用**：两家云端部分**均未核实**，以 Step 0 官方核查结果为准。OpenRouter 买 $10 额度可提高免费模型上限——**那是付费行为，$0 预算下不做**。
- **数据注意**：OpenRouter 免费路由的服务方可能记录或用提示词训练——**只用合成测试数据**。
- **风险**：免费模型名单轮换频繁；Groq 免费计划速率低，不适合高频调用；两家都是云端，断网即不可用，独立性靠本地 Ollama 兜底。
- **验证步骤**：同方案 A。

### 方案 C：纯本地推理后端 Ollama（零外部依赖）
- **技术路线**：全部逻辑模型映射到 Ollama 本地模型；不接任何云端 API 供应商；Router、网关、规划器全部走本地。
- **费用**：$0（模型权重开源免费，Ollama 免费开源）。
- **风险**：模型能力最弱；云端 1.5 核共享 CPU、无 GPU，本地推理速度可能很慢（小模型 smoke test 需实测）；不能验证“多后端切换”与“云端降级”，只能验证“本地降级”。
- **定位**：不是主方案，是兜底方案——任何云端免费层核查失败或不可用时，Jarvis 仍能以本方案独立运行，符合“外部 AI 全停也不瘫痪”的验收条件。

### 方案 D（否决）：DeepSeek 官方 API
- **结论：否决，不符合 $0 预算。**
- **依据**：多家第三方在 2026-10/11 读取 DeepSeek 官方定价页后一致称：DeepSeek API 无免费层、无注册赠金，按 token 预付费计费，需先充值。所谓“$5 新手赠金”未获官方页面证实，**不得作为免费方案**。
- **保留项**：DeepSeek 模型权重是 MIT 开源许可，可免费下载、本地用 Ollama 运行——这属于方案 C 的模型选项，不是云端 API 供应商。

## 3. 接入方式比较：直接适配器 vs LiteLLM Proxy（修订新增）

> LiteLLM Proxy 暂时不列为必选组件。以下比较供用户决定；未决定前不安装、不接入。

| 维度 | 直接适配器（在 router.py 内按后端写小适配器） | LiteLLM Proxy（自托管统一入口） |
|---|---|---|
| 费用 | $0（无新增组件） | $0（开源免费，自托管） |
| 复杂度 | 低：首批只有 2 个后端，且 Gemini、Groq、OpenRouter 均提供 OpenAI 兼容接口，适配器主要是 base_url + key + 模型名映射 | 中：多一个常驻服务进程，需部署、配置、版本锁定、健康检查 |
| 维护风险 | 低：每个后端 API 变化只改对应适配器；无第三方代理依赖 | 中：依赖 LiteLLM 的版本与安全状况（ADR-002 已记 2026-03 PyPI 事件，需锁定版本、验签、放内网）；代理本身出问题会挡住全部后端 |
| 必要性 | 首批 2 个后端、接口兼容时足够；后端超过 3 个或接口差异大时再评估 | 后端多、接口差异大、需要统一预算/限流/日志时才有明显收益 |
| 回滚 | 改回 Stub 只改 config | 需停掉代理服务再改回直连，多一步 |

- **建议**：首批 2 个后端先用直接适配器；LiteLLM 作为后续扩展选项，待后端增多或接口分化时再由用户决定是否引入。
- **决定权在用户**：本节只做比较，不预设结论。

## 4. 首批两个模型接入后端建议
- **推荐组合：Ollama 本地推理后端 + Gemini API 免费层（方案 A），以前提是 Gemini 的 Step 0 核查通过。**
- **备选组合：若 Gemini 的 Step 0 核查失败（需绑卡、无免费额度、政策已变），换 Groq 免费计划（方案 B 的一半），另一家仍为 Ollama 本地推理后端。**
- **选择理由**：一家本地（独立性兜底，$0 确定）+ 一家云端免费层（能力对照，$0 待核查），覆盖“本地优先 + 云端可选”与“模型可替换”两个原则；两家都失败时退到方案 C，系统仍能运行。
- **不建议的组合**：两家全是云端免费层（断网即全停，独立性无兜底）；DeepSeek API（不符合 $0）。

## 5. 费用分析（$0 硬约束）
| 项目 | 费用 | 说明 |
|---|---|---|
| Ollama + 本地模型 | $0 | 开源免费；云端已有虚拟电脑，无新增硬件 |
| Gemini API 免费层 | 未核实 | 以 Step 0 官方核查为准；不绑卡、不开通计费账户；核查失败即换方案 |
| Groq 免费计划 | 未核实 | 以 Step 0 官方核查为准；不升级到 Developer 计划 |
| OpenRouter :free | 未核实 | 以 Step 0 官方核查为准；不购买额度 |
| 直接适配器 | $0 | 无新增组件 |
| LiteLLM Proxy | 待定 | 不列为必选；若用户决定引入，自托管开源免费，但需评估维护成本 |
| 部署与运行 | $0 | 云端虚拟电脑已有；实体机部署演练用用户已有电脑，不买新硬件 |
| **合计** | **$0** | 任何一项核查出费用即停，记录原因与替代方案，不自行突破预算 |

## 6. 风险分析
| 风险 | 影响 | 缓解 |
|---|---|---|
| 免费层政策已变（需绑卡/无免费额度） | 方案 A/B 不成立 | Step 0 先核查再接入；备选组合与方案 C 兜底 |
| 免费层速率过低，测试做不完 | 验证不充分 | 测试用小样本、分批跑；记录“受速率限制未完成”的项，不谎报通过 |
| 免费层拿提示词训练/人工审核 | 真实用户数据外泄风险 | 只用合成测试数据；真实数据不上免费层 |
| 免费模型名单轮换、下线 | 映射失效 | Router 映射只改 config；定期核查名单；测试记录写明当时模型 ID 与日期 |
| 本地小模型在 1.5 核 CPU 上过慢 | 本地推理基线难看 | 只测小模型 smoke test；不拿云端 CPU 性能推断实体机性能（已在 P0 明确） |
| 为省钱擅自改架构 | 违背长期目标 | 红线：$0 是约束，不是改架构的理由；改架构需用户批准（ADR-010） |
| 误用未经核实的旧电脑配置 | 实体机方案与实际设备不符 | 先盘点再定方案（见第 7 节） |

## 7. 实体电脑部署：先盘点，再定方案（修订新增）
- **现状**：目前没有任何经核实的实体电脑配置信息。可行性报告里的硬件分析是分析，不是设备信息；云端审计（Ubuntu 24.04.5、4 vCPU 共享 1.5 核、6GB 内存、无 GPU）是云端虚拟电脑的配置，**不得代替实体电脑信息**。
- **盘点清单（S2-5 第一步，用户提供或现场确认）**：CPU 型号与核数、内存大小、磁盘容量与类型、GPU 型号与显存、操作系统与版本、Python 版本、网络条件、存储设备情况。
- **顺序**：盘点 → 根据盘点结果定本地模型（大小、量化）与部署方案 → 再做导出、安装、数据恢复、真机离线启动演练。不得在盘点前定本地模型与部署方案。
